## 1. Real vs Mock / Demo

The application runs in two distinct modes. **When the FastAPI backend is unreachable** (the common case for demo), `api.js` catches every Axios error and returns data from `mockData.js`. When the backend IS reachable, live DB queries are used.

| Feature / Number | Source in Demo Mode | Source in Live Mode |
|---|---|---|
| Total Projects count | Computed from `DEMO_PROJECTS.length` (22 objects in `mockData.js`) | `SELECT COUNT(*) FROM projects` via `get_dashboard()` in `dashboard.py` |
| Active Projects count | `DEMO_PROJECTS.filter(p.status === 'In Progress').length` | Same SQL logic on live `projects` table |
| High Risk Projects | `DEMO_PROJECTS.filter(['HIGH','CRITICAL'].includes(p.risk_level)).length` | Counts from `RiskAnalysis.risk_level` join |
| Critical Alerts | Hardcoded `DEMO_DASHBOARD.critical_alerts = 3` (not computed from `DEMO_ALERTS`) | `COUNT WHERE alerts.severity='CRITICAL' AND status='New'` |
| Total Sanctioned | Sum of `sanction_amount` across `DEMO_PROJECTS` | Sum of `projects.sanction_amount` |
| Total Expenditure | Sum of `actual_expenditure` across `DEMO_PROJECTS` | Sum of `projects.actual_expenditure` |
| Risk Distribution Pie | Computed from `DEMO_PROJECTS[*].risk_level` | Computed from `RiskAnalysis.risk_level` per project |
| Monthly Alert Trends | Hardcoded array in `DEMO_DASHBOARD.monthly_alert_trends` | Actual `alerts.created_at` dates bucketed by month |
| Top Risk Projects table | `DEMO_PROJECTS` sorted by `risk_score` desc, sliced to 8 | `risk_analyses` joined to `projects`, sorted |
| Fin vs Physical Progress chart | First 10 `DEMO_PROJECTS` | Top 10 by abs mismatch from DB |
| Risk score on each project (e.g. MPL-1003 = 88) | **100% hardcoded** in `DEMO_PROJECTS` objects in `mockData.js` | Computed by ML pipeline and stored in `risk_analyses` table |
| Sub-scores (financial_risk, execution_risk, etc.) | **100% hardcoded** in `DEMO_PROJECTS` | ML computation results persisted in `risk_analyses` |
| Alert list & contents | `DEMO_ALERTS` (10 hardcoded objects) | `alerts` DB table, seeded by `seed.py` running real ML |
| Investigation queue | `DEMO_INVESTIGATIONS` (5 hardcoded objects) | `investigations` DB table |
| Evidence records | `DEMO_EVIDENCE` (10 hardcoded objects) | `evidence` DB table |
| Compliance checks & scores | `DEMO_COMPLIANCE` (3 hardcoded projects, 6 rules each) | `compliance_checks` DB table |
| Analytics: district_risk | `DEMO_ANALYTICS.district_risk` (hardcoded 8 rows) | Computed from `RiskAnalysis` + `Project` join |
| Analytics: agency_risk | `DEMO_ANALYTICS.agency_risk` (hardcoded 8 rows) | Computed from `RiskAnalysis` + `Project` join |
| Analytics: monthly_expenditure | `DEMO_ANALYTICS.monthly_expenditure` (hardcoded 10 months) | **Also hardcoded on the backend** — `analytics.py` line ~47: `monthly_expenditure = [{"month": "Jan", ...}]` with literal values. Comment: "mock from project data — real impl would use FinancialRecord model" |
| Analytics: duplicate_trends | `DEMO_ANALYTICS.duplicate_trends` (hardcoded 4 months) | Falls back to same hardcoded list if no DB data |
| Analytics: Overall Risk Distribution Pie (Analytics page) | **Hardcoded inline** in `Analytics.jsx`: `[{ name: 'LOW', value: 12 }, ...]` — not even from `DEMO_ANALYTICS` | Not connected; still hardcoded even in live mode |
| Notifications dropdown | `NOTIFICATIONS` array in `mockData.js` (5 objects) | **Never replaced** — always mock regardless of backend status |
| "Demo" badge in Topbar | Shown when `isUsingDemoData()` returns true | — |

**Key finding:** Even when the backend IS live, `monthly_expenditure` in analytics and the `Overall Risk Distribution Pie` in `Analytics.jsx` remain hardcoded/disconnected from real data.

## 2. ML Modules — What Actually Runs

### `financial_anomaly.py`

- **Library used:** `scikit-learn` — `IsolationForest` + `LabelEncoder`
- **Execution condition:** `SKLEARN_AVAILABLE = True` AND `len(all_projects) >= 10`
- **What runs if condition not met:** `_statistical_score()` — deterministic fallback using z-score of expenditure ratio against same-type peers
- **Fallback when <10 projects:** Also `_statistical_score()`; if no same-type peers, uses absolute threshold `(ratio - 1.0) / 0.15`
- **Inputs:** `project` dict + `all_projects` list. Features: `sanction_amount`, `estimated_cost`, `actual_expenditure`, expenditure ratio, `project_type` (label-encoded), `district` (label-encoded), `agency` (label-encoded)
- **Output:** Float 0–100 (financial risk score)
- **Persisted?** Yes — written to `risk_analyses.financial_risk` on `/analyze`
- **Important note:** The Isolation Forest is trained fresh on the current dataset every time `/analyze` is called. There is no saved model file. With only 22 seed projects, the model trains on 22 samples — marginally sufficient (threshold is 10).

### `execution_risk.py`

- **Library used:** `xgboost` (for delay prediction only)
- **What runs:** `compute_execution_risk()` is pure Python math — always runs, no library dependency
- **XGBoost delay prediction:** `XGB_AVAILABLE` is checked but the function `predict_delay()` **always calls `_rule_based_delay()`** regardless. The docstring explicitly states: "For demo, always falls back to rule-based as we don't have a pre-trained model file." XGBoost is never actually executed.
- **Inputs to execution risk:** `financial_progress` (float), `physical_progress` (float)
- **Inputs to delay prediction:** full project dict (uses `status`, `start_date`, `expected_completion_date`, `physical_progress`, `financial_progress`)
- **Output:** `execution_risk` float 0–100; `delay_probability` float 0–1; `predicted_delay_days` int
- **Persisted?** Yes — `execution_risk`, `delay_probability`, `predicted_delay_days` all written to `risk_analyses`

### `duplicate_detection.py`

- **Libraries used:** `sentence-transformers` (primary), `scikit-learn` TF-IDF (secondary fallback), keyword Jaccard (final fallback)
- **What actually runs:** Three-tier cascade:
  1. If `sentence-transformers` installed AND model loads: uses `SentenceTransformer("all-MiniLM-L6-v2")` for embeddings
  2. Else if `sklearn` installed: TF-IDF cosine similarity
  3. Else: Jaccard overlap on word tokens
- **Geographical component:** Pure Python Haversine formula — always runs
- **Inputs:** target project dict, `all_projects` list. Text feature = `project_name + project_type + district`
- **Output:** `semantic_similarity` (%), `geographical_similarity` (%), `distance_km`, `matched_project` dict, `duplicate_risk` (0–100)
- **Persisted?** Yes — all fields written to `risk_analyses` columns `matched_project_id`, `semantic_similarity`, `geographical_similarity`, `distance_km`, `duplicate_risk`
- **Note:** Model is loaded lazily via `_get_st_model()` on first call; a global `_model` variable caches it within the process lifecycle.

### `compliance_engine.py`

- **Library used:** None — pure Python rule engine
- **Always executes:** Yes, no optional import
- **Inputs:** `project` dict, `evidence_list` (list of `{evidence_type, verification_status}` dicts)
- **Rules evaluated (6 total):**
  1. Required fields present (weight 20)
  2. Sanction date present (weight 15)
  3. Timeline validity — checks if today > expected_completion_date (weight 20)
  4. Progress updates recorded (weight 15)
  5. Completion evidence uploaded (weight 20)
  6. Supporting documentation (work order, no missing items) (weight 10)
- **Output:** `checks` list (rule, status, severity, reason), `compliance_score` (0–100), `compliance_risk` (100 – score)
- **Persisted?** Yes — each check written as a row to `compliance_checks` table with `compliance_score` denormalized on every row

### `evidence_risk.py`

- **Library used:** None — pure Python
- **Always executes:** Yes
- **Inputs:** `evidence_list` — list of dicts with `evidence_type` and `verification_status`
- **Required evidence types checked:** Project Photo, Completion Certificate, Payment Record, Work Order, Supporting Document
- **Scoring:** `missing_penalty = (missing/5) * 60`, `mismatch_penalty = (mismatch/5) * 30`, `pending_penalty = (pending/5) * 10`. If no evidence at all: returns 90.0
- **Output:** Float 0–100
- **Persisted?** Yes — `evidence_risk` written to `risk_analyses`

### `unified_score.py`

- **Library used:** None — pure arithmetic
- **Always executes:** Yes
- **Inputs:** Five sub-scores (floats), weights from `settings` (default: financial=0.25, execution=0.20, duplicate=0.15, compliance=0.15, evidence=0.25)
- **Formula:** `score = financial*0.25 + execution*0.20 + duplicate*0.15 + compliance*0.15 + evidence*0.25`
- **Risk level thresholds:** LOW ≤ 30, MEDIUM ≤ 60, HIGH ≤ 80, CRITICAL > 80
- **Also generates:** `flagged_reasons` list (human-readable explanations for each risk factor) via `generate_flagged_reasons()`
- **Output:** `unified_risk_score` (0–100), `risk_level` string, `flagged_reasons` list
- **Persisted?** Yes — `unified_risk_score`, `risk_level`, `flagged_reasons` (JSON string) written to `risk_analyses`

## 3. Dashboard Data Source

**In demo mode** (backend unreachable) — `fetchDashboard()` in `api.js`:

| KPI Card | Computation |
|---|---|
| Total Projects | `DEMO_PROJECTS.length` → 22 |
| Active Projects | `DEMO_PROJECTS.filter(p.status === 'In Progress').length` |
| High Risk Projects | `DEMO_PROJECTS.filter(['HIGH','CRITICAL'].includes(p.risk_level)).length` |
| Critical Alerts | `DEMO_DASHBOARD.critical_alerts` → hardcoded `3` (ignores `DEMO_ALERTS`) |
| Total Sanctioned | `DEMO_PROJECTS.reduce((s, p) => s + p.sanction_amount, 0)` |
| Total Expenditure | `DEMO_PROJECTS.reduce((s, p) => s + p.actual_expenditure, 0)` |

**In live mode** (backend up) — `GET /api/dashboard` → `dashboard.py::get_dashboard()`:

| KPI Card | Query Path |
|---|---|
| Total Projects | `db.query(Project).all()` → `len(projects)` |
| Active Projects | `sum(1 for p in projects if p.status == "In Progress")` |
| High Risk Projects | Iterates projects, looks up `ra_map.get(p.project_id).risk_level`, counts HIGH/CRITICAL |
| Critical Alerts | `db.query(Alert).all()` → `sum(1 for a if a.severity == 'CRITICAL' and a.status == 'New')` |
| Total Sanctioned | `sum(p.sanction_amount for p in projects)` |
| Total Expenditure | `sum(p.actual_expenditure for p in projects)` |

The `+3` trend badge on "Active Projects" and `+2` on "High Risk Projects" shown in `Dashboard.jsx` are **hardcoded strings** (`trendValue="+3"`, `trendValue="+2"`) passed as props to `StatCard` — they do not come from any calculation.

## 4. Score Calculation Trace

### Clicking "Re-analyse" on ProjectDetails.jsx

1. **Frontend** (`ProjectDetails.jsx`, `handleAnalyze()`):
   - Calls `analyzeProject(projectId)` from `api.js`
   - `api.js::analyzeProject()` → `safePost('/api/projects/{projectId}/analyze', {})`
   - If backend unreachable: returns `{ success: true, message: 'Analysis queued (demo mode)' }` (no real computation)
   - Shows toast: "Analysis queued. Results will update shortly."
   - **Does NOT refresh the displayed scores** — user must navigate away and back

2. **Backend** (`projects.py::analyze_project()`):
   - Queries `projects` table for target project → `_project_to_dict(p)`
   - Queries `projects` table for ALL projects → list of dicts (for peer comparison)
   - Queries `evidence` table for this project's evidence
   - Calls `risk_service.analyse_project(project_dict, all_project_dicts, evidence_list)`

3. **`risk_service.py::analyse_project()`** — orchestrates in order:
   - Step 1: `compute_financial_risk(project, all_projects)` → `financial_anomaly.py`
   - Step 2: `compute_execution_risk(fp, pp)` → `execution_risk.py`
   - Step 3: `predict_delay(project, all_projects)` → always `_rule_based_delay()` in `execution_risk.py`
   - Step 4: `find_duplicates(project, all_projects)` → `duplicate_detection.py`
   - Step 5: `run_compliance_checks(project, evidence_list)` → `compliance_engine.py`
   - Step 6: `compute_evidence_risk(evidence_list)` → `evidence_risk.py`
   - Step 7: `compute_unified_score(f, e, d, c, ev)` → `unified_score.py`
   - Step 8: `get_risk_level(score)` → thresholds in `unified_score.py`
   - Step 9: `generate_flagged_reasons(...)` → `unified_score.py`

4. **DB Write** (back in `projects.py::analyze_project()`):
   - Queries `risk_analyses` for existing row; creates if not found
   - Writes all 10 fields: `financial_risk`, `execution_risk`, `duplicate_risk`, `compliance_risk`, `evidence_risk`, `unified_risk_score`, `risk_level`, `matched_project_id`, `semantic_similarity`, `geographical_similarity`, `distance_km`, `delay_probability`, `predicted_delay_days`, `flagged_reasons`
   - `db.commit()`
   - Returns `{ success, message, risk_level, unified_risk_score }`

5. **Number appears on screen**: Only if the user **re-navigates** to the ProjectDetails page, triggering a fresh `GET /api/projects/{id}/risk` call. The current `handleAnalyze()` does not re-fetch after analysis completes — it only shows a toast.

## 6. Database Tables

### Table: `projects`
- **Model:** `app/models/project.py::Project`
- **Columns:** `id` (PK), `project_id` (unique), `project_name`, `mp_name`, `constituency`, `district`, `state`, `project_type`, `agency`, `sanction_amount`, `estimated_cost`, `actual_expenditure`, `physical_progress` (0–100), `financial_progress` (0–100), `sanction_date`, `start_date`, `expected_completion_date`, `actual_completion_date`, `latitude`, `longitude`, `status`, `created_at`, `updated_at`
- **Data held:** Core project metadata and financial/progress numbers
- **Seed data:** Yes — 22 projects seeded by `data/seed.py::SEED_PROJECTS`

### Table: `risk_analyses`
- **Model:** `app/models/project.py::RiskAnalysis`
- **Columns:** `id` (PK), `project_id` (indexed), `financial_risk`, `execution_risk`, `duplicate_risk`, `compliance_risk`, `evidence_risk`, `unified_risk_score`, `risk_level`, `matched_project_id`, `semantic_similarity`, `geographical_similarity`, `distance_km`, `delay_probability`, `predicted_delay_days`, `flagged_reasons` (JSON TEXT), `analysed_at`
- **Data held:** ML output for each project analysis run
- **Seed data:** Yes — one row per project, computed during seeding

### Table: `alerts`
- **Model:** `app/models/alert.py::Alert`
- **Columns:** `id` (PK), `alert_id` (unique), `project_id`, `project_name`, `district`, `alert_type`, `severity`, `risk_score`, `reason`, `status`, `detected_date`, `created_at`, `updated_at`
- **Alert types:** FINANCIAL_ANOMALY, PROGRESS_MISMATCH, POSSIBLE_DUPLICATE, DELAY_WARNING, COMPLIANCE_VIOLATION, MISSING_EVIDENCE
- **Data held:** Generated alerts from ML analysis
- **Seed data:** Yes — auto-generated by `determine_alert_type()` for each project during seeding

### Table: `investigations`
- **Model:** `app/models/investigation.py::Investigation`
- **Columns:** `id` (PK), `investigation_id` (unique), `project_id`, `project_name`, `district`, `risk_score`, `risk_level`, `risk_factors` (JSON TEXT), `priority`, `assigned_officer`, `status`, `notes`, `created_at`, `last_updated`
- **Data held:** Investigation workflow records for HIGH/CRITICAL projects
- **Seed data:** Yes — auto-created for all HIGH/CRITICAL risk projects during seeding

### Table: `evidence`
- **Model:** `app/models/evidence.py::Evidence`
- **Columns:** `id` (PK), `project_id`, `project_name`, `evidence_type`, `upload_date`, `verification_status`, `risk_status`, `notes`, `file_name`, `file_path`, `created_at`, `updated_at`
- **Data held:** Document/photo records for projects
- **Seed data:** Yes — 12 records for MPL-1001, MPL-1002, MPL-1003, MPL-1008, MPL-1021

### Table: `compliance_checks`
- **Model:** `app/models/compliance.py::ComplianceCheck`
- **Columns:** `id` (PK), `project_id`, `project_name`, `rule`, `status`, `severity`, `reason`, `compliance_score` (denormalized project score on every row), `created_at`, `updated_at`
- **Data held:** Individual compliance rule results per project (6 rules × N projects = 6×22 = 132 rows)
- **Seed data:** Yes — all rules evaluated for all 22 projects during seeding

### Table: NOT YET DEFINED — `financial_records`
- Referenced in `analytics.py` comment: "real impl would use FinancialRecord model" — **does not exist**

## 9. What Is Missing vs The Upgrade Spec

Based on gaps visible in the current code relative to a full production MPLADS risk intelligence system:

### Authentication & Authorization
- **Missing:** No real JWT authentication endpoint. `POST /api/auth/login` does not exist. `loginDemo()` writes a fake `demo_token_{timestamp}` to sessionStorage. The backend has no auth middleware — all endpoints are open.
- **Missing:** Role-based access control. All four roles (MP, District Officer, State Officer, Ministry) see identical UI and data.

### Notifications
- **Missing:** Real-time notifications. The bell dropdown always shows the 5 hardcoded `NOTIFICATIONS` from `mockData.js`. No `GET /api/notifications` endpoint. No WebSocket or polling mechanism.

### Alert Management
- **Missing:** `PUT /api/alerts/{id}/status` — "Mark Reviewed" button on `RiskAlerts.jsx` has no handler and no backend endpoint.
- **Missing:** Alert acknowledgement workflow.

### Project Update
- **Missing:** `PUT /api/projects/{id}` — no way to update project data (progress %, expenditure) from the UI after creation.

### Score Refresh After Analysis
- **Missing:** After "Re-analyse" completes, `ProjectDetails.jsx` does not automatically re-fetch and display the new scores. The `handleAnalyze()` function only shows a toast.

### Financial Records Model
- **Missing:** `FinancialRecord` database table referenced in `analytics.py` comment. Monthly expenditure is permanently hardcoded.

### Evidence Upload
- **Missing:** Actual file upload functionality. Evidence records exist in the DB but `file_path` is always null. There is no `POST /api/evidence` or `PUT /api/evidence/{id}` endpoint.

### Comparison View
- **Missing:** Side-by-side project comparison. "Compare Projects" button navigates to the matched project's own detail page, not a dedicated comparison view.

### Settings Persistence
- **Missing:** All Settings page values are local React state only. There is no `PUT /api/settings` endpoint. Risk thresholds and weights defined in Settings do not affect any backend computation.

### Analytics Completeness
- **Missing:** The `Overall Risk Distribution` pie in `Analytics.jsx` is permanently hardcoded `[LOW:12, MEDIUM:3, HIGH:4, CRITICAL:3]` — it does not respond to live data even when the backend is connected.
- **Missing:** Date range filtering actually changes output. The `3m/6m/1y` buttons send `range` param to the backend but `analytics.py` ignores it.

### Geo Map
- **Missing:** Real map tiles. The risk map is an SVG with a grid background and hand-placed text labels. There is no integration with a mapping library (Leaflet, Google Maps, Mapbox, etc.).

### Audit Logging
- **Missing:** No audit trail of who viewed/actioned what project. The `Investigation` model has `notes` and `assigned_officer` but no change history.

### Export
- **Missing:** No PDF/CSV export of reports, alerts, or project lists.
